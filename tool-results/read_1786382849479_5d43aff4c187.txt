  5086→Task ID: P3-DEVELOPMENT (Phase 3 — Wire development techniques into composeLead)
  5087→Agent: Z.ai Code (main)
  5088→
  5089→THE PROBLEM (code-verified):
  5090→MelodyEngine defined 7 classical development techniques (transpose, invert, retrograde, fragment, elongate, shorten, sequence) but MusicalDirector.composeLead() only applied `octaveShift` (±12 semitones). The lead motif repeated with octave changes but never TRANSFORMED — no transposition, no inversion, no rhythmic diminution/augmentation, no sequencing. This is why the lead sounded repetitive: it lacked the classical motivic development that Beethoven/Bach/film composers use to make a melody EVOLVE across phrases rather than just repeat.
  5091→
  5092→ROOT CAUSE:
  5093→- composePhrase() called `melody.newPhrase(energy)` which generates a FRESH motif each phrase (no continuity across phrases).
  5094→- composeLead() then read from that fresh motif via `melody.nextNote()` — applying only an octave shift per phase.
  5095→- The development techniques existed in MelodyEngine but were called only INSIDE buildPhrase() for the A→A'→B→A'' internal phrase structure, NOT across phrases for the high-level development arc.
  5096→
  5097→THE FIX (5 classical transformations, 1 per DevelopmentPhase):
  5098→
  5099→  - statement  (phase 0): IDENTITY       — play the motif as-is (the "thesis").           label: "A"
  5100→  - variation  (phase 1): TRANSPOSE +3rd OR FRAGMENT (first 4 notes) — varied repeat.    label: "A' (transposed +3rd)" or "A' (fragment)"
  5101→  - contrast   (phase 2): INVERT          — flip the contour upside-down (B from A).      label: "B (inverted)"
  5102→  - climax     (phase 3): SHORTEN (×2 faster) + SEQUENCE up (×2) → MERGE — climbing run. label: "A'' (diminution + sequence)"
  5103→  - resolution (phase 4): ELONGATE (×2 slower) — calm augmentation.                      label: "A (augmentation)"
  5104→
  5105→Pipeline (per phrase, inside composeLead):
  5106→  1. baseMotif = melody.getCurrentMotif()           // the fresh motif newPhrase() just generated
  5107→  2. { motif: transformed, label } = transformMotifForPhase(phase, baseMotif, rng)
  5108→  3. melody.setMotif(transformed)                    // rebuilds A A' B A'' phrase table from transformed motif
  5109→  4. for each step: melody.nextNote() → returns notes from the TRANSFORMED motif's phrase table
  5110→  5. return label → stored in Phrase.motifIds[] for UI display
  5111→
  5112→The transformed motif drives the A section (the "thesis" of the phrase). buildPhrase() still derives A' / B / A'' from it as usual, so the WHOLE 8-bar phrase inherits the transformation — e.g. in the climax phase, A is diminished+sequenced, A' is a transposed version of THAT (still fast), B is fresh contrasting material, A'' is augmented (which would slow it back down — a known compounding effect that's acceptable since the A section itself carries the diminution intensity).
