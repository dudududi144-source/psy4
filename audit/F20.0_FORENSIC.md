# F20.0 — FORENSIC AUDIT: MUSICAL VOCABULARY IS TOO SMALL

**HEAD:** `d2cabac` (F19) · **Method:** Code-level verification of all 28 questions.

## THE 28 QUESTIONS — ANSWERED

### Q1: How many musical strategies exist?
**Answer: 0.** There are no "strategies" in the codebase. The word "strategy" appears 0 times in MusicalSession.ts. The system has hardcoded generators per style (FULL_ON/DARK/PROGRESSIVE/ACID) but these are parameter presets, not behavioral strategies.

### Q2: How many bass grammars?
**Answer: 1 hardcoded + 1 learned.** The hardcoded `generateBass()` uses `beatDegrees` arrays that change per section. The learned `generateLearnedBass()` uses a single `BassGrammar` with one interval transition matrix. There is no concept of "rolling bass" vs "syncopated bass" vs "acid bass" as distinct strategies.

### Q3: How many lead grammars?
**Answer: 1 hardcoded + 1 learned.** Same pattern. The learned `MelodicGrammar` has one interval histogram. No concept of "call/response" vs "arpeggio" vs "counter-melody" as distinct strategies.

### Q4: Can lead change phrasing strategy?
**Answer: NO.** The lead always uses the same generation approach: sample intervals from histogram → apply contour preference → emit notes. There is no "staccato" vs "sustained" vs "fragmented" mode.

### Q5: Can bass change groove strategy?
**Answer: NO.** The bass always uses the same pattern structure: notes on beats + offbeats. There is no "rolling" vs "sparse" vs "driving" mode. The only variation is which scale degrees are used.

### Q6: Can kick/bass/lead influence each other during composition?
**Answer: PARTIALLY.** The `CandidateGenerator` reads `state.bassLastMidi` to avoid register collision (line 127-128). But the bass generator does NOT read the kick pattern. The kick generator does NOT read the bass. There is no real-time interaction — only the lead's post-hoc avoidance of the bass register.

### Q7: How many sound families?
**Answer: 4 presets.** The PRESETS array (psyLive.ts:57-114) defines 4 presets with different `bassWave/bassCut/bassQ/leadWave/leadCut/leadQ`. These are parameter variations, not sound families. A "saturated rolling bass" and a "dark bass" would need different synthesis architectures, not just different cutoff frequencies.

### Q8: Does sound generation differ between families or just preset parameters?
**Answer: Just parameters.** All voices use the same oscillator+filter+saturation architecture. The only differences are wave type, cutoff, Q, and gain levels. No FM, no wavetables, no noise-based synthesis, no granular, no ring mod.

### Q9: How many FX types?
**Answer: 2.** Delay and reverb. Both are static bus effects with no musical timing or intent.

### Q10: Are FX musical events with timing/intent?
**Answer: NO.** There are no risers, impacts, sweeps, filter opens, reverse hits, or noise bursts. FX are always-on bus processors controlled by sliders.

### Q11: Fills?
**Answer: YES (basic).** Kick fills at phrase end (steps 14-15 or 13-14). Bass walks at phrase end. These are hardcoded, not strategic.

### Q12: Call/response?
**Answer: NO.** The motif system has PHRASE_STRUCTURE = [0,0,1,0,0,1,2,0] which creates A-A-B-A-A-B-C-A phrase groups. But there is no actual call/response between bass and lead, or between phrases. The lead doesn't "answer" the bass.

### Q13: Counter-melody?
**Answer: NO.** There is only one lead voice. No counter-melody layer.

### Q14: Acid strategy?
**Answer: NO.** The ACID style changes hat/bass counts and adds syncopation, but there is no 303-style acid bass (resonant filter sweep, squelchy envelope). The bass synthesis is identical — just sawtooth through LPF.

### Q15: Arpeggio strategy?
**Answer: NO.** The lead never arpeggiates. It plays melodic lines from interval histograms.

### Q16: Texture/atmosphere strategy?
**Answer: NO.** There is no texture/atmosphere layer. No pads, no drones, no noise sweeps, no ambient layers.

### Q17: Transition grammar?
**Answer: NO.** Transitions are limited to kick fills and bass walks at phrase ends. No risers, downlifters, impacts, filter sweeps, or density builds/releases as musical events.

### Q18: Can arrangement switch musical strategy?
**Answer: NO.** The arrangement arc (INTRO→STATEMENT→...→RESOLUTION) only changes lead density and beat degrees. It does not change the musical approach, sound family, or strategy.

### Q19: Can learned context select a new strategy?
**Answer: NO.** Learning updates grammar parameters (interval distributions, rhythm patterns) but never selects a different strategy. The system always uses the same generation approach.

### Q20: Can radio learn sound character without copying?
**Answer: YES (partially).** `TimbreProfile` extracts brightness, noisiness, and spectral characteristics. It maps these to `synthParams` (bassWave, bassCut, leadWave, leadCut). But only 4 of 8 synthParams are actually applied.

### Q21: Does timbre learning reach synthesis parameters?
**Answer: PARTIALLY.** `applyLearnedTimbre()` (psyLive.ts:739-751) overrides bassWave, bassCut, leadWave, leadCut. But bassSaturation, leadSaturation, hatDecay, hatBrightness are computed but never applied.

### Q22: Layered synthesis?
**Answer: YES.** Kick = sub sine + body sine + transient. Bass = sub sine + mid saw. Lead = 3-voice unison. Hats = noise + HPF + bandpass. This is good — F15 built it.

### Q23: Filter/envelope/distortion/reverb/delay automation?
**Answer: NO.** All parameters are static. No filter sweeps, no envelope automation, no distortion changes, no reverb/delay throws. The only automation is per-note filter envelopes on bass and lead.

### Q24: Stereo/motion language?
**Answer: PARTIAL.** Lead has stereo panning (-0.6/0/+0.6 on 3 oscillators). Everything else is mono. No stereo motion, no width automation, no Haas effect.

### Q25: Sidechain/ducking for coexistence?
**Answer: GAIN-BASED, not sidechain.** Duck gain nodes reduce bus gain when radio is loud. This is NOT sidechain compression (which would duck bass when kick hits, creating the classic psytrance pump). No sidechain compressor exists.

### Q26: Persistent SoundDNA/soundbank?
**Answer: NO.** Zero hits for SoundDNA, SoundBank, MaterialBank in the codebase. All learning is in-memory.

### Q27: Save successful sound family and generate descendants?
**Answer: NO.** No persistence, no sound family model, no descendant generation.

### Q28: Why does the lead still not "sit"?
**Answer:** The lead generator (CandidateGenerator) has 3 problems:
1. **No bass rhythm awareness** — it knows `bassLastMidi` (pitch) but not WHEN the bass plays. It can't leave holes where bass is busy.
2. **No harmonic context** — it samples from a generic interval histogram, not from intervals that fit the current bass degree.
3. **No phrase role** — it doesn't know if it's a "call", "response", "development", or "cadence". All bars are treated the same.

The lead "sits" when it complements the bass rhythmically, harmonically, and registrally. Currently it only avoids register collision — the most basic form of complement.

## ROOT CAUSE

The system has **one musical world** with parameter variations. It needs **multiple musical worlds** (strategies) that it can select between based on context, energy, and learning.

The current architecture:
```
MusicalSession.planBar()
  → generateKick()     [hardcoded grammar, 1 approach]
  → generateBass()     [hardcoded degrees OR learned grammar, 1 approach]
  → generateHats()     [hardcoded per style, 1 approach]
  → generateLead()     [learned grammar via CandidateGenerator, 1 approach]
```

The target architecture:
```
MusicalSession.planBar()
  → selectStrategy(context)  [chooses bass/lead/groove/texture strategy]
  → generateWithStrategy()   [generates using the SELECTED strategy]
  → scoreCandidates()        [evaluates against relational context]
  → rewardUpdate()           [feeds back into strategy weights]
```
